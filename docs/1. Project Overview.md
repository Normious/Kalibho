# Project overview: Kalibho

## What is Kalibho?

Kalibho is a centralized slug generation and collision-checking service. It turns any
human-readable string (title, product name, headline, category) into a URL-safe, unique,
SEO-friendly slug, and guarantees uniqueness per tenant.

`"Hello World!"` → `hello-world`: generate once, use everywhere, never collide.

## Core purpose

Every content-driven service needs slugs. Without a shared engine each service writes its
own slugify logic (inconsistent), hits unique-constraint violations on insert, and breaks
links on rename. Kalibho is the one slug engine for all of them:

- **Shop A**: product URLs (`/products/wireless-headphones`)
- **Gig4Gig**: job categories (`/jobs/plumbing-services`)
- **AaaS**: profile URLs (`/u/alice-banda`)
- **Emerge Fund**: blog posts; **Pgi**: invoice file names

## Technology stack

- **Runtime**: Node.js 20+ (ES modules)
- **Framework**: Fastify 4 (schema validation, hooks)
- **Database**: SQLite via `better-sqlite3@12` (UNIQUE-constraint atomicity, WAL mode)
- **Unicode**: native `String.normalize('NFKD')`, zero extra deps
- **Auth**: `X-API-Key` header → `projects` table (multi-tenant)
- **Logging**: pino (`pino-pretty` outside production)

## Key features

- Generate slugs with Unicode normalization (`Café Déjà Vu` → `cafe-deja-vu`)
- Collision handling: `suffix` (`-2`, `-3`) / `timestamp` / `uuid` strategies
- Reserve slugs with TTL + auto-expiry purge every 60s
- Check availability, resolve canonical + alias redirects
- Rename with alias preservation (no broken links, SEO-safe)
- Batch generation (up to 100 per request)
- Per-project namespaces (Shop A slugs ≠ Gig4Gig slugs)
- Full audit history + usage stats (collision rate, op breakdown)

## Project structure

```
kalibho/
├── docs/                    ← you are here (see README.md for entry point)
├── migrations/0001_init.sql ← projects / slugs / slug_history
├── src/
│   ├── server.js            ← Fastify wiring, route registration order
│   ├── config.js            ← env-driven config
│   ├── db.js                ← SQLite access + atomic claims
│   ├── migrate.js / seed.js
│   ├── slug/                ← slugify.js, generator.js, strategies.js
│   ├── routes/              ← generate, check, reserve, rename, resolve, history
│   └── middleware/auth.js   ← X-API-Key → request.project
├── test/                    ← slugify.test.js, api.test.js (node:test)
├── Dockerfile               ← node:20-slim + build toolchain
└── docker-compose.yml
```

## Getting started

```bash
npm install
npm run migrate
npm run seed     # Shop A + Gig4Gig API keys
npm start        # :4010
```

Docker (the volume starts empty: seed once):

```bash
docker compose up -d --build
docker compose exec kalibho node src/seed.js
curl http://localhost:4010/health
```
